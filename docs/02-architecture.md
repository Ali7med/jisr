## ٣. السيرفر

| الوحدة | المسؤولية | التقنية | الحالة |
|---|---|---|---|
| **REST API** | ٣٠ مساراً: مصادقة · تكاملات · حسابات · أجهزة · أوامر · سجلّ · أتمتة · مشاهد · إشعارات · عائلة | Fastify + TypeBox | ✅ |
| **طبقة التكاملات** | عقد `Integration` وتنفيذاته — إضافة شركة = ملف + سطر | TypeScript | ✅ |
| **WS Push** | قناة لكل مستخدم، **تصادق برسالة لا برابط** | `@fastify/websocket` | ✅ |
| **أنبوب الحالة** | يقارن، يحفظ **ما تغيّر فقط**، ينشر، ويُخطر المحرّك | داخلي | ✅ |
| **مستهلك رسائل Tuya** | اشتراك دائم يستقبل التغيّرات لحظياً | SDK Node.js | ⏳ محجوب بـ T-V ([P2.1](03-roadmap.md)) |
| **محرّك الأتمتة** | مُشغِّل (حالة · وقت) + شرط + إجراء، ٢٤/٧ | **داخل العملية** ([ADR-0015](adr/0015-automation-engine-in-process.md)) | ✅ |
| **مسجّل التاريخ** | كل تغيّر → القاعدة، بسياسة استبقاء من اليوم الأول | Prisma + PostgreSQL | ✅ |
| **المصادقة والأذون** | JWT + تدوير رمز التجديد · عائلة بأذون لكل جهاز | `@fastify/jwt` + `@node-rs/argon2` | ✅ |
| **الإشعارات** | تُخزَّن ثم تُدفع عبر القناة | داخلي | ✅ · دفع FCM ⏳ |

**نموذج البيانات المحوري يُنقل كما هو:** `Integration` · `IntegrationInfo` (تُبنى منه شاشة الربط ديناميكياً) · `Capability` (`toggle` · `range` · `mode` · `text`) · `Device` · `DeviceCategory`. التصميم مثبت وموثّق في [ADR-0003](adr/0003-dynamic-ui-from-specifications.md).

## ٤. لوحة الويب

**Next.js + React + TypeScript** — تشارك `packages/shared` مع السيرفر، فتغيير عقد API يكسر البناء فوراً في الطرفين.

| القسم | الوظيفة | الحالة |
|---|---|---|
| **ربط الحسابات** | اختيار الشركة → نموذج يُبنى من `IntegrationInfo.fields` → السيرفر يتحقّق قبل الحفظ | ✅ |
| **الأجهزة** | عرض وتحكّم تفاؤلي، وحالة القناة اللحظية معروضة دائماً | ✅ |
| **السجلّ والرسوم** | رسم SVG خالص — خطّ واحد لسلسلة واحدة لا يستحق مكتبة تُشحن وتُصان | ✅ |
| **بانِي الأتمتة** | «إذا … و… فـ …» بصرياً بالعربي — **بلا YAML إطلاقاً** ([الدراسة § 4](01-study.md)) | ⏳ [P5.2](03-roadmap.md) |
| **المستخدمون** | دعوة أفراد العائلة، صلاحيات لكل جهاز | ⏳ الواجهة (الـ API جاهز) |

> **حدّ موثّق:** رموز الجلسة في `localStorage`. الانتقال إلى كعكة `httpOnly` يقتضي أن يُصدر السيرفر كعكات لا رموزاً حاملة — تغيير في عقد المصادقة يستحق قراراً مستقلاً قبل خدمة مستخدمين حقيقيين.

## ٥. تطبيق الهاتف

**عميل رفيع** ([ADR-0009](adr/0009-server-mandatory-thin-client.md)): لا كود تكاملات، لا أسرار، لا اتصال بأي شركة.

```
lib/data/api/       ← JisrApiClient (REST) + RealtimeClient (WS)
lib/data/repositories/device_cache.dart   ← كاش قراءة فقط
lib/ui/             ← بقي كما هو تماماً
```

- شاشة تسجيل دخول بدل شاشة مفاتيح Tuya ✅
- **لا استقصاء دوري** — القناة اللحظية ✅
- شاشة التفاصيل ديناميكية من `Capability` كما كانت، والقدرات تصل من سيرفرنا ✅
- **سلوك الانقطاع صريح**: آخر حالة معروفة بطابع زمني عربي، والتحكّم معطّل ([ADR-0014](adr/0014-availability-target.md)) ✅

> **ما يبقى من أسرار على الجهاز:** رمزا الجلسة وحدهما — لا مفتاح شركة واحد.

## ٦. تدفّقات البيانات

**تحكّم:**
```
الهاتف ──POST /devices/tuya:abc/commands──▶ السيرفر ──▶ Tuya ──▶ الجهاز
Tuya ──رسالة فورية──▶ السيرفر ──WS──▶ كل أجهزة العائلة  (< ٢ ثانية)
```

**تغيّر خارجي (ما كان مستحيلاً بلا سيرفر):**
```
أحدهم أطفأ المصباح يدوياً → Tuya → السيرفر → WS → هاتفك يتحدّث لحظياً
```

**أتمتة:**
```
قراءة تصل → أنبوب الحالة (تغيّرت؟) → المحرّك يقيّم الشرط → أمر + إشعار
```
لا طابور بين الحدث والإجراء ([ADR-0015](adr/0015-automation-engine-in-process.md))، والإشعار **يُخزَّن ثم يُدفع** فيجده صاحبه ولو كان هاتفه مغلقاً.

**سقوط السيرفر:**
```
التطبيق يعرض آخر حالة معروفة من الكاش المحلي + «آخر تحديث قبل ١٢ دقيقة»
عناصر التحكّم معطّلة · رسالة عربية: «تعذّر الاتصال بجسر — نحاول مجدداً»
التحكّم متوقف (قرار واعٍ — ADR-0009 · نموذج العطل في ADR-0014)
```

## ٧. الأمان

| الطبقة | الإجراء |
|---|---|
| أسرار التكاملات | AES-GCM في القاعدة بمفتاح من متغيّر بيئة خارجها — تسريب dump لا يكشفها. **حدّ معروف:** المفتاح يعيش على نفس المضيف، فاختراق الـ VPS يكشف المفتاح والبيانات معاً. يُرقّى إلى KMS/Vault عند أول من يتحقّق: خروج القاعدة إلى مضيف منفصل، أو تجاوز ١٠٠ حساب مربوط |
| **الهاتف** | **لا يحمل أي سرّ إطلاقاً** — يحمل JWT فقط. الثغرة القديمة ([ADR-0002](adr/0002-direct-connection-with-abstraction.md)) أُغلقت |
| المصادقة | JWT قصير العمر + refresh · كلمات المرور Argon2 |
| النقل | HTTPS/WSS فقط — Caddy بشهادات تلقائية |
| الصلاحيات | كل طلب يُفحص، و**المنع هو الأصل**: عضو العائلة لا يرى جهازاً إلا بإذن صريح ولا يتحكّم إلا إن شمله الإذن. **404 لما لا يراه و403 لما يراه ولا يتحكّم به** — إخفاء وجود جهاز يظهر في قائمته لا يحمي شيئاً ويجعل العطل غامضاً |
| رموز الدعوة والتجديد | تُخزَّن **مجزّأة** (SHA-256) لا خامّاً: تسريب القاعدة لا يمنح جلسة ولا يفتح مساحة أحد. وقبول الدعوة يشترط تطابق البريد، فرمز مُعاد توجيهه لا يُستعمل |
| التشغيل | **Rate limiting عام على كل المسارات** (`@fastify/rate-limit`) مع سقف أشدّ على `/auth` · السجلّات لا تطبع أسراراً أبداً |
| تدوير المفاتيح | مفتاح التشفير وأسرار JWT قابلة للتدوير بلا توقّف: إعادة تشفير تدريجية وقبول التوكنات القديمة حتى انتهائها |

## ٨. النشر

| البند | القرار |
|---|---|
| الحاويات | `docker-compose.prod.yml`: `server` + `postgres` + `caddy` + `backup` — Postgres **بلا منفذ منشور**، والسيرفر بمستخدم غير جذر |
| الهجرات | تُطبَّق عند إقلاع السيرفر: نسخة جديدة لا تعمل على مخطّط قديم |
| الاستضافة | **Hetzner CX22 (2 vCPU · 4GB) ≈ €4.59/شهر + Coolify مجاني** — يستوعب المنظومة بمساحة واسعة |
| النسخ الاحتياطي | `pg_dump` يومي خارج السيرفر — **و«تمرين استعادة» ربع سنوي موثّق**: نسخة لم تُختبَر استعادتها ليست نسخة |
| المراقبة | `/health` (العملية حيّة) و**`/health/ready`** (القاعدة تستجيب) — التمييز مقصود، وعلى الثاني يُقاس التوفّر. فحص خارجي إلزامي: مراقبة على نفس الخادم تسقط معه |
| دليل التشغيل | [`docs/runbook.md`](runbook.md): نشر وتراجع · أعطال شائعة · تدوير المفتاح · تمرين الاستعادة |
| **هدف التوفّر** | **99.5% شهرياً معلن + صفحة حالة عامة** ([ADR-0014](adr/0014-availability-target.md)) — وعتبة رقمية تُفعّل إعادة النظر في [ADR-0009](adr/0009-server-mandatory-thin-client.md) |
| الاستعادة من الصفر | `docs/runbook.md`: نسخة احتياطية ← VPS جديد ← DNS. يُكتب في P2 ويُختبر مع كل تمرين استعادة — علاج مخاطرة «الشخص الواحد» |
| بيئة التجريب | لا staging منفصل الآن (قرار واعٍ لتوفير الكلفة)؛ الحماية: هجرات قابلة للتراجع + نشر خارج أوقات الذروة + `/health` يوقف النشر الفاشل |
| CI | `tsc --noEmit` + `vitest` للسيرفر والويب · `flutter analyze` + `flutter test` للهاتف |

## ٩. قواعد ثابتة

1. **لا اسم شركة خارج `server/src/integrations/`** — السجلّ هو المكان الوحيد الذي يذكرها.
2. **الهاتف والويب لا يعرفان أي شركة** — يستهلكان `Device` و`Capability` الموحّدين فقط.
3. **ما لا نفهمه يُعرض خاماً، لا يُخفى** — على الثلاثة.
4. **كل رسالة خطأ عربية وتشرح ما العمل.**
5. **عقود API في `packages/shared` فقط** — لا تعريف نوع مكرّر بين السيرفر والويب.
6. **الأسرار لا تدخل git ولا السجلّات** — على كل المستويات.
7. **إضافة شركة جديدة = ملف تكامل واحد + سطر في السجلّ.** لا شاشة جديدة في الهاتف ولا في الويب.
