## ١. الصورة الكاملة

```
        ┌──────────────────┐        ┌──────────────────┐
        │  تطبيق الهاتف     │        │   لوحة الويب      │
        │  Flutter Android │        │   Flutter Web    │
        │  (تحكّم يومي)     │        │  (إدارة وربط)     │
        └────────┬─────────┘        └────────┬─────────┘
                 │      كود Flutter واحد      │
                 │    HTTPS (REST) + WSS      │
        ┌────────▼────────────────────────────▼─────────┐
        │              Jisr Server  (Dart)              │
        │ ┌─────────┐ ┌──────────┐ ┌─────────────────┐  │
        │ │ REST API│ │WS Push   │ │ محرّك الأتمتة    │  │
        │ ├─────────┤ ├──────────┤ ├─────────────────┤  │
        │ │ Auth/JWT│ │ مسجّل     │ │ مجدول التحديث   │  │
        │ │ المستخدمون│ │ التاريخ  │ │ (poll + Pulsar) │  │
        │ └─────────┘ └────┬─────┘ └─────────────────┘  │
        │        ┌─────────▼──────────┐                 │
        │        │     jisr_core      │  ← نفس الحزمة    │
        │        │ Integration · Tuya │    في التطبيق    │
        │        └─────────┬──────────┘                 │
        │        ┌─────────▼──────────┐                 │
        │        │ PostgreSQL (مشفّر)  │                 │
        │        └────────────────────┘                 │
        └───────┬───────────────────────┬───────────────┘
         Pulsar │ (فوري، server-to-server)│ HTTPS موقّع
        ┌───────▼──────┐         ┌───────▼──────┐
        │  Tuya Cloud  │         │ شركات أخرى…  │
        └──────────────┘         └──────────────┘
```

**الفكرة المحورية:** حزمة **`jisr_core`** (Dart خالص: عقد `Integration` + النماذج + تكامل Tuya كاملاً) تعمل **بلا تعديل** في مكانين:
- داخل التطبيق → **الوضع المباشر** (بلا سيرفر، كما يعمل اليوم)
- داخل السيرفر → **الوضع المُدار** (كل القدرات الإضافية)

هذا ليس ترفاً معمارياً — هو ما يجعل السيرفر **إضافة** لا **إعادة كتابة**، ويُبقي التطبيق حيّاً عند سقوط السيرفر.

## ٢. هيكل المستودع (Monorepo)

```
D:\Apps\Projects\jisr\
├── packages/
│   └── jisr_core/            ★ Dart خالص — يُستخرج من apps/mobile (المرحلة P0)
│       ├── lib/domain/           العقد + النماذج (Integration, Device, Capability…)
│       └── lib/integrations/     tuya/ · (لاحقاً: tasmota/ · broadlink/ …)
│
├── apps/
│   ├── mobile/               ★ تطبيق Flutter — موجود ويعمل (أندرويد + ويب لاحقاً)
│   │   └── lib/                  ui/ · config/ · routing/ · data/ (يستهلك jisr_core)
│   ├── server/                 السيرفر (Dart shelf) — المرحلة P1
│   │   └── lib/                  api/ · auth/ · realtime/ · automations/ · store/
│   └── web/                    محجوز — القرار الحالي: الويب من apps/mobile نفسه (Flutter Web)
│
├── docs/                       هذا التوثيق + ADRs + مراجع
└── README.md
```

> **لماذا الويب من نفس كود الموبايل؟** Flutter Web يعطينا لوحة الإدارة من نفس الشاشات
> والثيم والنصوص، بتخطيط متجاوب. لوحة ويب منفصلة (React مثلاً) تعني نظام تصميم ثانياً
> ولغة ثانية وازدواج كل شاشة — نؤجّلها حتى يثبت أنها ضرورية. ([ADR-0007](adr/0007-dart-server-monorepo.md))

## ٣. المكوّنات

### أ. `jisr_core` — النواة المشتركة
- **ما هي:** كل ما لا يعتمد Flutter: `Integration` (العقد) · `Device` · `Capability` · `Account` · `IntegrationException` · تكامل Tuya كاملاً (signer/client/mapper).
- **قاعدة حديدية:** لا `import 'package:flutter/...'` داخلها إطلاقاً — شرط عملها على السيرفر.
- **الحالة:** الكود موجود وجاهز داخل `apps/mobile/lib` — الاستخراج ميكانيكي (المرحلة P0).

### ب. السيرفر — `apps/server`
| الوحدة | المسؤولية |
|---|---|
| **REST API** | `/auth` · `/accounts` · `/devices` · `/devices/{id}/commands` · `/automations` · `/history` |
| **WS Push** | قناة لكل عميل؛ يدفع تغيّرات الحالة فور وصولها — الهاتف يتخلّى عن الـ polling |
| **مجدول التحديث** | يشترك بـ **Tuya Pulsar** (متاح الآن — server-to-server) + polling احتياطي؛ تحديث واحد يخدم كل أفراد العائلة بدل استعلام من كل هاتف |
| **محرّك الأتمتة** | مشغّلات (تغيّر حالة/وقت/شروق-غروب) + شروط + إجراءات؛ يعمل ٢٤/٧ — ما لا يستطيعه تطبيق هاتف |
| **مسجّل التاريخ** | يكتب كل تغيّر حالة → رسوم بيانية بلا حدود Tuya (٧ أيام) |
| **Auth** | مستخدمون + JWT + صلاحيات لكل فرد عائلة على مستوى الجهاز |

**التقنية:** Dart + `shelf` (خفيف، من فريق Dart، بلا توليد كود — امتداد لروح [ADR-0005](adr/0005-no-code-generation.md)) · PostgreSQL · Docker.
لماذا ليس Serverpod؟ يفرض توليد كود ونمط RPC ومتطلبات تشغيلية ثقيلة (Redis/Postgres إلزامية من اليوم الأول) — [المقارنة](https://dartform.dev/blog/serverpod-dart-frog-shelf-which-dart-backend) والتفصيل في [ADR-0007](adr/0007-dart-server-monorepo.md).

### ج. التطبيق — `apps/mobile`
- كما هو اليوم، مع تغيير واحد جوهري لاحقاً: تنفيذ جديد للعقد باسم **`ServerIntegration`** يكلّم سيرفرنا بدل Tuya مباشرة، ويستمع للـ WS بدل المؤقّتات.
- **مبدّل الوضع:** مباشر ↔ مُدار. عند تعذّر السيرفر يعرض التطبيق التحوّل المؤقت للوضع المباشر.
- بناء الويب: نفس الكود، تخطيط متجاوب، وأقسام الإدارة (المستخدمون، الأتمتة المتقدمة) تظهر في الويب أولاً.

## ٤. تدفّقات البيانات الأساسية

**تحكّم (الوضع المُدار):**
```
الهاتف ──POST /devices/tuya:abc/commands──▶ السيرفر
السيرفر ──jisr_core.TuyaIntegration.execute()──▶ Tuya
Tuya ──Pulsar: تغيّرت الحالة──▶ السيرفر ──WS──▶ كل أجهزة العائلة (< ٢ ثانية)
```

**تحديث فوري (ما كان مستحيلاً بلا سيرفر — [ADR-0004](adr/0004-polling-instead-of-pulsar.md)):**
```
جارك أطفأ المصباح يدوياً → Tuya → Pulsar → السيرفر → WS → هاتفك يتحدّث لحظياً
```

**أتمتة:**
```
حساس الحرارة > 30° ──Pulsar──▶ السيرفر: قاعدة «إذا الحرارة > 30 شغّل المكيّف»
                                └──▶ execute(المكيّف, on) + إشعار push للهاتف
```

**انقطاع السيرفر:**
```
الهاتف يفشل بالوصول ──▶ يعرض: «السيرفر متعذّر — التحوّل للوضع المباشر؟»
──▶ TuyaIntegration المحلي يعمل بمفاتيح المستخدم المخزّنة على الجهاز
```

## ٥. الأمان

| الطبقة | الإجراء |
|---|---|
| أسرار التكاملات | تُشفَّر في القاعدة (AES-GCM) بمفتاح من متغيّر بيئة خارج القاعدة — تسريب dump لا يكشفها |
| المصادقة | JWT قصير العمر + refresh token · كلمات المرور بـ Argon2 |
| النقل | HTTPS/WSS فقط — Caddy مع شهادات تلقائية |
| الصلاحيات | كل طلب يمرّ بفحص: هل هذا الجهاز ضمن أجهزة هذا المستخدم/العائلة؟ |
| الهاتف (الوضع المباشر) | كما اليوم: `flutter_secure_storage`، والقيد الموثّق في [ADR-0002](adr/0002-direct-connection-with-abstraction.md) يظلّ سارياً عليه |
| الحماية التشغيلية | Rate limiting على `/auth` · سجلّات لا تطبع أسراراً أبداً (قاعدة قائمة في الكود) |

## ٦. النشر

| البند | القرار |
|---|---|
| الحاويات | Docker Compose: `server` + `postgres` + `caddy` |
| الاستضافة | VPS واحد (Hetzner/DO، ~5$) يكفي مئات المستخدمين الأوائل |
| النسخ الاحتياطي | `pg_dump` يومي خارج السيرفر |
| المراقبة | فحص صحّة `/health` + تنبيه عند السقوط |
| CI | `dart analyze` + `dart test` لكل حزمة عند كل دفعة (يُضاف مع P1) |

## ٧. قواعد ثابتة

امتداد لقواعد المشروع منذ بدايته:

1. **`jisr_core` لا تعرف Flutter ولا السيرفر** — نماذج وعقود فقط.
2. **لا اسم شركة خارج `integrations/`** — السجلّ هو المكان الوحيد الذي يذكرها.
3. **ما لا نفهمه يُعرض خاماً، لا يُخفى** — على الهاتف والويب والسيرفر.
4. **كل رسالة خطأ عربية وتشرح ما العمل.**
5. **الوضع المباشر لا يُكسر أبداً** — كل ميزة سيرفر تُبنى كإضافة قابلة للغياب.
6. **الأسرار لا تدخل git ولا السجلّات** — على كل المستويات.
