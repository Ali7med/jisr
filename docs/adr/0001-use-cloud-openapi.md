# ADR-0001 — Cloud OpenAPI بدل App SDK

**الحالة:** ✅ معتمد
**التاريخ:** 2026-09-01

## السياق

المطلوب: تطبيق هاتف يعرض أجهزة Tuya المرتبطة بحساب المستخدم، يعرض قراءاتها، ويتحكم بها.

Tuya توفّر ثلاث طرق للوصول:

| الطريقة | الوصف |
|---|---|
| **Cloud OpenAPI** | REST + HMAC عبر HTTPS |
| **Smart Home App SDK** | SDK أصلي Android/iOS |
| **البروتوكول المحلي (LAN)** | UDP discovery + TCP محلي |

## القرار

**نستخدم Cloud OpenAPI.** الإقران يتم من تطبيق **Smart Life** الرسمي، خارج نطاق مشروعنا.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|---|---|
| **Smart Home App SDK** | يضيف ~٥ أسابيع (AAR/Framework + platform channels + مراجعة Tuya) واشتراكاً مدفوعاً، مقابل ميزة واحدة: **إقران أجهزة جديدة داخل التطبيق** — وهي غير مطلوبة. العرض والقراءة والتحكم متطابقة في الطريقتين. |
| **البروتوكول المحلي (LAN)** | `local_key` يتغيّر عند إعادة إقران الجهاز فينكسر الاتصال بصمت؛ لا يدعم كل الفئات؛ لا يعمل خارج الشبكة المحلية. مناسب لأداة، لا لتطبيق يُستخدم يومياً. |

## النتائج

### إيجابية
- كل المتطلبات مغطّاة بـ HTTP فقط — لا كود أصلي، لا platform channels
- يعمل من أي مكان، لا يشترط الشبكة المحلية
- طبقة رقيقة يسهل اختبارها وحدوياً

### سلبية
- **لا يمكن إقران جهاز جديد من داخل التطبيق** — المستخدم يستخدم Smart Life
- التبعية الكاملة على سحابة Tuya: انقطاعها = تعطّل التطبيق
- استهلاك حصة API الشهرية

### ما يُبطل هذا القرار
لو أصبح الإقران داخل التطبيق متطلّباً حقيقياً (مثلاً عند تسليم التطبيق لمستخدمين غير تقنيين)، يُعاد فتح الخيار مع تقدير تكلفته الكاملة.
