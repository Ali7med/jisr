# ADR-0013 — PostgreSQL + Prisma

**الحالة:** ✅ معتمد
**التاريخ:** 2026-09-02

## السياق

[الهيكلية § 3](../02-architecture.md#٣-السيرفر) تعتمد PostgreSQL وPrisma فعلياً بلا قرار موثّق. الخيار يقيّد المستقبل (الهجرات · نمو السجلّ التاريخي · حدود الـ ORM) فيستحق ADR.

ثلاثة أحمال مختلفة الطبائع في منتج واحد:
1. **علائقية صرفة**: مستخدمون · عائلات · صلاحيات · قواعد أتمتة — علاقات وقيود سلامة مرجعية
2. **أسرار مشفّرة**: مفاتيح التكاملات (AES-GCM) — قراءة نادرة، حساسية قصوى
3. **سلاسل زمنية**: `state_history` — كتابة كثيفة متنامية، قراءة تجميعية للرسوم

## القرار

**PostgreSQL قاعدة واحدة للأحمال الثلاثة، وPrisma طبقة الوصول والهجرات.**

- `state_history` يبدأ جدولاً عادياً بفهرس `(device_id, recorded_at)`، ويُقسَّم شهرياً (partitioning) عند الحاجة.
- **سياسة استبقاء معلنة من اليوم الأول**: قراءات خام لمدة محدودة ثم تجميع (دقيقة ← ساعة ← يوم). بلا سياسة، ينمو الجدول بلا سقف وتصير كلفة القرص هي المشكلة لا بطء الاستعلام.
- الهجرات بـ `prisma migrate` حصراً — ملتزمة في git ومطبَّقة في النشر، لا تعديل يدوي على قاعدة الإنتاج.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|---|---|
| **SQLite** | كافٍ لمستخدم واحد، ويسقط أمام كتابة متزامنة من مستهلك الرسائل + محرّك الأتمتة + طلبات المستخدمين |
| **TimescaleDB من اليوم الأول** | ممتاز للسلاسل الزمنية، لكنه يقيّد خيارات الاستضافة ويضيف تعقيداً قبل وجود حجم يبرّره — والانتقال إليه لاحقاً **امتداد على نفس Postgres لا هجرة قاعدة** |
| **MongoDB** | نموذجنا علائقي بامتياز (مستخدم ← عائلة ← جهاز ← صلاحية)؛ فقدان القيود المرجعية خسارة صافية |
| **Drizzle / Kysely** | أخفّ وأقرب لـ SQL، لكن هجرات Prisma الناضجة وأنواعه المولّدة توفّر جهداً حقيقياً على مطوّر واحد |
| **قاعدة منفصلة للسلاسل الزمنية** | مكوّن تشغيلي ثانٍ (نسخ احتياطي · مراقبة · ترقية) لمكسب لا نحتاجه بعد |

## النتائج

### إيجابية
- قاعدة واحدة: نسخة احتياطية واحدة، مراقبة واحدة، ومعاملة واحدة تشمل كل شيء
- أنواع Prisma المولّدة تُغذّي `packages/shared` بلا ازدواج تعريف
- مسار ترقية واضح: فهرسة ← تقسيم ← TimescaleDB، بلا تغيير قاعدة

### سلبية
- **Prisma يولّد كوداً** — استثناء صريح من [ADR-0005](0005-no-code-generation.md) المقيَّد نطاقه بتطبيق الهاتف
- سلسلة زمنية في Postgres عادي تحتاج انتباهاً يدوياً (فهارس · تقسيم · استبقاء) لا يوفّره امتداد مخصّص
- عميل Prisma ثقيل في البدء البارد — غير مهم لخادم دائم

### ما يُبطل هذا القرار
بطء استعلامات الرسوم رغم التقسيم والتجميع ⇒ TimescaleDB (امتداد لا هجرة). أو حاجة استعلامات لا يعبّر عنها Prisma بنظافة ⇒ إنزالها إلى SQL خام **داخل** Prisma لا استبداله.
