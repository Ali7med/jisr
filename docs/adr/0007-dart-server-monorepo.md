# ADR-0007 — Dart للسيرفر · Monorepo · الويب من Flutter

**الحالة:** ✅ معتمد
**التاريخ:** 2026-09-01

## السياق

قرار [ADR-0006](0006-central-server-platform.md) يستلزم ثلاثة اختيارات تقنية: لغة السيرفر، تنظيم المستودع، وتقنية لوحة الويب.

## القرار

### ١. السيرفر: Dart + `shelf`
الحجة الحاسمة: **طبقة التكاملات كلها Dart خالص أصلاً** (signer/client/mapper/عقد Integration — بُنيت هكذا عمداً منذ اليوم الأول). سيرفر Dart يعيد استخدامها حرفياً بصفر إعادة كتابة؛ أي لغة أخرى تعني كتابة تكامل Tuya مرتين وصيانته مرتين إلى الأبد.

`shelf` تحديداً (لا Serverpod ولا Dart Frog): من فريق Dart، بلا توليد كود (روح [ADR-0005](0005-no-code-generation.md))، ولا يفرض Redis/بنية RPC من اليوم الأول — Serverpod «الأكثر تقدماً لكنه الأعقد بدءاً بمتطلبات Docker/Postgres/Redis» ([مقارنة 2026](https://dartform.dev/blog/serverpod-dart-frog-shelf-which-dart-backend)).

### ٢. المستودع: Monorepo في `D:\Apps\Projects\jisr`
```
packages/jisr_core   ← النواة المشتركة (تُستخرج في P0)
apps/mobile          ← التطبيق (Flutter)
apps/server          ← السيرفر (Dart)
docs/                ← دراسة وهيكلية وقرارات على مستوى المنظومة
```
تعديل واحد على العقد يظهر للطرفين في نفس الـ commit — مستودعات منفصلة تعني جحيم مزامنة إصدارات لفريق من شخص واحد.

### ٣. الويب: Flutter Web من `apps/mobile` نفسه
كود واحد ⇒ الثيم والنصوص والشاشات والـ view models كلها مرة واحدة. لوحة منفصلة (React) تعني لغة ثانية ونظام تصميم ثانياً وازدواج كل شاشة. مجلد `apps/web` محجوز إن ثبت مستقبلاً أن لوحة الإدارة تحتاج ما لا يقدّمه Flutter Web.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|---|---|
| Node/NestJS أو Python/FastAPI للسيرفر | نظامهما البيئي أوسع، لكن خسارة إعادة استخدام jisr_core أفدح من أي مكسب |
| Serverpod | يفرض codegen + RPC + Redis — ثقل غير مبرّر لحجمنا |
| مستودعات منفصلة | تكلفة مزامنة بلا فائدة لفريق واحد |
| React للوحة الويب | ازدواج كامل للواجهة بلغة ثانية |

## النتائج

### إيجابية
- تكامل جديد يُكتب مرة ويعمل فوراً على الهاتف (مباشر) والسيرفر (مُدار)
- لغة واحدة عبر كامل المنظومة — تنقّل ذهني صفري
- الويب «مجاني» تقريباً بعد P2

### سلبية
- نظام Dart البيئي للسيرفرات أصغر (بلا مكتبات جاهزة لكل شيء) — نكتب بعض الأساسيات بأنفسنا
- Flutter Web أثقل تحميلاً أولياً من صفحة React خفيفة — مقبول للوحة إدارة، ليس لموقع عام
- Monorepo يتطلّب انضباطاً في حدود الحزم (تحرسه قاعدة «لا Flutter في jisr_core»)

### ما يُبطل هذا القرار
- احتياج مكتبة سيرفر حرجة لا بديل لها خارج Node/Python ⇒ خدمة جانبية صغيرة بتلك اللغة، لا إعادة كتابة
- ثبوت قصور Flutter Web للوحة ⇒ يُفعَّل `apps/web` منفصلاً
