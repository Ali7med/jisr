# ADR-0005 — بلا توليد كود

**الحالة:** ✅ معتمد
**التاريخ:** 2026-09-01

## السياق

المعتاد في مشاريع Flutter استخدام `freezed` + `json_serializable` للنماذج، و`riverpod_generator` للـ providers. كلها تعتمد على `build_runner`.

نماذج هذا المشروع سبعة، وأشكال JSON من Tuya بسيطة ومسطّحة.

## القرار

**نكتب `fromJson` و`copyWith` والـ providers يدوياً.** لا `freezed` ولا `json_serializable` ولا `riverpod_generator`.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|---|---|
| **freezed + json_serializable** | يضيف `build_runner` لكل تعديل نموذج، وملفات `.g.dart`/`.freezed.dart` تضاعف عدد الملفات — مقابل توفير ~200 سطر في مشروع بسبعة نماذج |
| **riverpod_generator** | الـ providers هنا قليلة ومباشرة؛ التوليد يخفي شجرة الاعتماديات التي نريدها ظاهرة في `config/dependencies.dart` |

## النتائج

### إيجابية
- `flutter analyze` يعمل مباشرة بلا خطوة بناء
- لا ملفات مولّدة تشوّش المستودع
- **التحليل النحوي مرئي وقابل للتعديل** — وهذا مهم: استجابات Tuya غير منتظمة، و`values` يصل نصّاً يحوي JSON، والتعامل معه احتاج منطقاً مخصّصاً (`DpDefinition._parseValues`) لا يُنتجه مولّد

### سلبية
- كتابة `fromJson` و`copyWith` يدوياً — عرضة لخطأ بشري
- لا مساواة بالقيمة تلقائياً (نستخدم `AsyncValue` من Riverpod للمقارنة على مستوى الحالة)
- حقل جديد في نموذج يتطلّب تعديلاً في موضعين (الحقل + `fromJson`)

### ما يُبطل هذا القرار
تجاوز النماذج ~15 نموذجاً، أو ظهور أخطاء متكرّرة في `fromJson` اليدوي. الانتقال إلى `freezed` تدريجي — نموذج بنموذج — ولا يتطلّب إعادة كتابة شاملة.
