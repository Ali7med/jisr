# ADR-0002 — اتصال مباشر خلف واجهة مجرّدة

**الحالة:** ⛔ **مَنسوخ بـ [ADR-0009](0009-server-mandatory-thin-client.md)** — الهاتف صار عميلاً رفيعاً بلا اتصال مباشر. يبقى هذا الملف لتوثيق سياق القرار وتجريد `Integration` الذي انتقل للسيرفر.
**التاريخ:** 2026-09-01

## السياق

توقيع طلبات Tuya يتطلّب `Access Secret`. وضعه داخل التطبيق يعني أنه **قابل للاستخراج من ملف الـ APK خلال دقائق**، ومن يحصل عليه يسيطر على كل أجهزة المشروع.

الحل الصحيح أمنياً: سيرفر وسيط يحتفظ بالسرّ ويوقّع نيابة عن التطبيق. لكن ذلك يضيف مكوّناً كاملاً يجب بناؤه واستضافته وصيانته — قبل أن يرى المستخدم أول جهاز على الشاشة.

## القرار

**التطبيق يتصل بـ Tuya مباشرة**، لكن كل الوصول يمرّ عبر واجهة مجرّدة واحدة:

```dart
abstract interface class TuyaService { … }   // lib/data/services/tuya_service.dart
```

التنفيذ الحالي `TuyaCloudService` يتصل مباشرة. عند إضافة backend لاحقاً نكتب `TuyaBackendService implements TuyaService` ونغيّر **سطراً واحداً** في `config/dependencies.dart`.

السرّ يُخزَّن في `flutter_secure_storage` (Android Keystore) — يحمي من قراءة الملفات على الجهاز، **لا** من فكّ الـ APK.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|---|---|
| **بناء backend من البداية** | يؤخّر أول نتيجة مرئية بأسبوع أو أكثر، وقد يتغيّر التصميم بعد أول تشغيل حقيقي |
| **اتصال مباشر بلا تجريد** | أبسط بقليل الآن، لكنه يجعل نقل الـ backend لاحقاً تعديلاً يمسّ كل شاشة |
| **تعمية السرّ داخل الكود** | أمان زائف — الـ obfuscation يؤخّر الاستخراج دقائق لا أكثر |

## النتائج

### إيجابية
- أول نتيجة مرئية خلال أيام لا أسابيع
- لا سيرفر يُستضاف ولا يُصان
- الانتقال للـ backend لاحقاً **لا يمسّ أي شاشة ولا نموذج عرض**

### سلبية
- 🔴 **`Access Secret` مستخرَج من الـ APK.** مقبول لتطبيق شخصي على هاتف صاحب الحساب؛ **غير مقبول لتطبيق منشور.**
- لا يمكن استخدام Pulsar للدفع الفوري ([ADR-0004](0004-polling-instead-of-pulsar.md))
- لا طبقة تخزين مؤقّت مشتركة بين الأجهزة

### ما يُبطل هذا القرار
**أي من هذه يوجب بناء سيرفر وسيط (تحقّق لاحقاً بـ [ADR-0006](0006-central-server-platform.md) — انظر [خارطة الطريق](../03-roadmap.md)):**
- نشر التطبيق على متجر أو توزيعه خارج جهاز صاحب الحساب
- أكثر من مستخدم
- الحاجة للتحديث الفوري بدل الـ polling
- تجاوز حصة API بسبب كثرة الأجهزة أو المستخدمين
