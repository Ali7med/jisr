# قرارات معمارية (ADR)

سجلّ **لماذا** بُني المشروع بهذا الشكل. كل ملف يوثّق قراراً واحداً وبدائله المرفوضة.

## القاعدة
- ADR **لا يُعدَّل** بعد اعتماده. لو تغيّر القرار، اكتب ADR جديداً يَنسَخه واذكر ذلك في كليهما.
- كل قرار يغيّر بنية الكود أو يقيّد الخيارات المستقبلية يستحق ADR.
- **الاستثناء الوحيد — «التعديل الملحق»:** يجوز شطب (`~~نص~~`) بندٍ بطل، بشرط إلحاق ملاحظة تُحيل للقرار الناسخ. الغرض توجيه القارئ لا إعادة كتابة التاريخ؛ النص الأصلي يبقى مقروءاً.
- **تواريخ القرارات 0001–0009 هي تواريخ توثيق لا اتخاذ** — دُوِّنت دفعة واحدة عند تأسيس المستودع. ما بعدها تواريخ اتخاذ فعلية.

### الحالات المعتمدة
`✅ معتمد` · `🟡 مقترح — مسودّة` · `⛔ مَنسوخ بـ ADR-YYYY` · `❌ مرفوض` · `✅ معتمد — عُدِّل بـ ADR-YYYY` (بندٌ منه بطل، وجوهره سارٍ)

## القالب

```markdown
# ADR-XXXX — <العنوان>

**الحالة:** معتمد | مقترح | مرفوض | مَنسوخ بـ ADR-YYYY | معتمد — عُدِّل بـ ADR-YYYY
**التاريخ:** YYYY-MM-DD

## السياق
ما المشكلة؟ ما القيود؟

## القرار
ما اخترناه، بجملة واضحة.

## البدائل المرفوضة
| البديل | لماذا رُفض |

## النتائج
### إيجابية
### سلبية
### ما يُبطل هذا القرار
```
