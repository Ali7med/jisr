# 03 — خارطة الطريق

**آخر تحديث:** 2026-09-01

---

## ما أُنجز قبل هذه الخارطة ✅

- تطبيق Flutter كامل يعمل بالوضع المباشر: قائمة أجهزة، تفاصيل ديناميكية من القدرات، تحكّم تفاؤلي، رسوم، تعريب RTL كامل
- **طبقة تكاملات مجرّدة** (`Integration` + `IntegrationRegistry`) وتكامل Tuya كامل خلفها
- 12 اختبار توقيع بمرجع خارجي · `flutter analyze` نظيف بقواعد مشدّدة · APK يُبنى
- ⚠️ **لم يُجرَّب استدعاء Tuya حقيقي بعد** — T-V أدناه يسبق كل شيء

---

## T-V — التحقق الحقيقي 🔴 **يسبق كل المراحل**

> بلا هذه الخطوة نبني برجاً على أساس غير مفحوص.

- [ ] **V.1** إعداد حساب Tuya (دليل: [reference/tuya.md](reference/tuya.md)) والحصول على المفاتيح الأربعة
- [ ] **V.2** `dart run tool/tuya_probe.dart` من `apps/mobile` — توثيق الأجهزة الفعلية
- [ ] **V.3** تشغيل التطبيق على الهاتف: عرض + قراءات + أمر تحكّم ناجح
- [ ] **V.4** إصلاح أي فرق بين أشكال الاستجابات الفعلية والمتوقعة

**القبول:** فيديو/لقطة لجهاز حقيقي يُتحكَّم به من التطبيق.

---

## P0 — استخراج `jisr_core` (أيام)

- [ ] **P0.1** إنشاء `packages/jisr_core` ونقل `domain/` + `data/integrations/` إليها
- [ ] **P0.2** `apps/mobile` تعتمدها بـ `path:` — بلا أي تغيير سلوكي
- [ ] **P0.3** نقل اختبارات التوقيع للحزمة + اختبارات `TuyaMapper` و`Capability` (الدَّين المؤجّل)
- [ ] **P0.4** CI بدائي: سكربت يفحص الحزمتين معاً

**القبول:** `flutter test` و`dart test` أخضران، والتطبيق يعمل كما قبل الاستخراج تماماً.

---

## P1 — السيرفر MVP (2–3 أسابيع)

- [ ] **P1.1** هيكل `apps/server` (shelf) + `/health`
- [ ] **P1.2** Auth: تسجيل/دخول، JWT + refresh، Argon2
- [ ] **P1.3** قاعدة البيانات: users · accounts (مشفّرة AES-GCM) · devices_cache
- [ ] **P1.4** ربط حساب Tuya عبر السيرفر (نفس `TuyaIntegration` من jisr_core)
- [ ] **P1.5** REST: devices · snapshot · commands · history (تمرير لـ Tuya)
- [ ] **P1.6** WS: قناة أحداث `device_state_changed` من polling السيرفر
- [ ] **P1.7** Docker Compose (server + postgres + caddy) على VPS تجريبي

**القبول:** `curl` بتوكن JWT يجلب الأجهزة وينفّذ أمراً من خارج الشبكة المنزلية.

---

## P2 — التطبيق يتحوّل عميلاً (1–2 أسبوع)

- [ ] **P2.1** `ServerIntegration implements Integration` في التطبيق (REST + WS)
- [ ] **P2.2** شاشة دخول/تسجيل + مبدّل الوضع (مباشر ↔ مُدار)
- [ ] **P2.3** إلغاء polling التطبيق في الوضع المُدار — الاستماع للـ WS
- [ ] **P2.4** سلوك الانقطاع: عرض التحوّل المؤقت للوضع المباشر
- [ ] **P2.5** أول بناء **Flutter Web** — نفس الكود، تخطيط متجاوب

**القبول:** هاتفان لنفس الحساب يريان تغيير أحدهما لحظياً · الويب يفتح نفس اللوحة.

---

## P3 — ما يتفوّق به على HA فعلياً (3–4 أسابيع)

- [ ] **P3.1** مسجّل التاريخ الخاص: كل تغيّر حالة → قاعدة البيانات → رسوم بلا حدود Tuya
- [ ] **P3.2** محرّك الأتمتة v1: مشغّل (حالة/وقت) + شرط + إجراء — يعمل ٢٤/٧
- [ ] **P3.3** باني أتمتة بصري عربي في التطبيق: «إذا … و… فـ …»
- [ ] **P3.4** Tuya **Pulsar** بدل الـ polling — التحديث < ٢ ثانية
- [ ] **P3.5** إشعارات Push (سيناريو: كاشف دخان/تسرّب → إشعار فوري)

**القبول:** مقاييس [الدراسة § 8](01-study.md#٨-مقاييس-النجاح) للأشهر الثلاثة محقّقة.

---

## P4 — العائلة والصلاحيات (2 أسابيع)

- [ ] **P4.1** دعوة أفراد عائلة (رابط/رمز) لحسابات فرعية
- [ ] **P4.2** صلاحيات لكل فرد على مستوى الجهاز (الطفل: غرفته فقط)
- [ ] **P4.3** سجلّ نشاط: مَن فعل ماذا ومتى

---

## P5 — تكامل ثانٍ + توسعة (مستمر)

- [ ] **P5.1** تكامل ثانٍ يثبت عمومية العقد — مرشّحان: **Tasmota/MQTT** (محلي، يفتح باب اللاسحابي) أو **eWeLink/Sonoff** (سحابي، جمهور واسع)
- [ ] **P5.2** المشاهد (Scenes) عبر الشركات: «مساء الخير» يطفئ Tuya ويشغّل Sonoff معاً — **ميزة لا يقدّمها أي تطبيق شركة**
- [ ] **P5.3** لوحة طاقة عربية: استهلاك اليوم/الشهر، تقدير الكلفة بالدينار
